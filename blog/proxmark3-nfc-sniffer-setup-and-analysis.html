Exploring Proxmark3: My Notes on Setting Up an NFC Sniffer and Tag Analysis

July 27, 2026 · 6 min read
Quang Nguyen
Software Engineer & Open Source Enthusiast

Recently, I bought a Proxmark3 device to learn more about hardware-level NFC and RFID protocol analysis. I wanted to see how wireless signals are exchanged between tag readers and smart cards under the hood.

To keep my host environment clean, I set up the Proxmark3 client inside a Docker container on Ubuntu 24.04. After flashing and verifying the device, I scanned a sample ISO 14443-A tag (MIFARE Classic 1K) to analyze its UID structure, manufacturer memory blocks, and security settings.

In this post, I want to share my notes, what I learned from testing the device, and how to run tag diagnostic commands using Proxmark3.

What I Learned About Proxmark3 and NFC Tag Analysis​

When I first unboxed the Proxmark3, it looked like a simple circuit board with dual antennas. However, reading the hardware documentation and executing diagnostic commands revealed how powerful it is:

  1. Dockerized Environment Setup: Running the Proxmark3 client inside a Docker container allows seamless device mapping over USB serial (/dev/ttyACM0) without polluting the host operating system with build dependencies.
  2. Antenna Tuning: Using hw tune measures the power output in millivolts across both High Frequency (HF 13.56 MHz) and Low Frequency (LF 125 kHz) antennas to confirm optimal signal quality.
  3. ISO 14443-A Anticollision Handshake: Commands like hf search capture the low-level handshake parameters (ATQA 00 04, SAK 08, and 4-byte UID CF 6A 8F 6C) sent during initial card selection.
  4. Block 0 Manufacturer Data Structure: Sector 0 Block 0 contains the card UID, a Block Check Character (BCC) XOR checksum, and factory batch metadata.
  5. Static PRNG Security Risks: Running hf mf info detects pseudo-random number generator (PRNG) behavior. Finding a static nonce (01200145) indicates a weak clone chip or Chinese Magic Tag vulnerable to key recovery attacks.

Testing and Walkthrough​

Here are the practical steps I followed to set up the device, launch the client shell, and inspect the tag.

Step 1: Connecting Device and Launching Docker Shell​

After connecting the Proxmark3 via USB, I launched the containerized client using the ./pm3-docker.sh wrapper script. This script opens an interactive terminal connected directly to the Proxmark3 hardware.

Step 2: Hardware Verification and High-Frequency Tag Scanning​

Inside the Proxmark3 prompt, I ran hw version to confirm the client version and hardware memory. Then, I placed the test card on the antenna and ran hf search to detect ISO 14443-A signaling. Finally, running hf mf info printed detailed sector key information and PRNG status.

How Block 0 and Tag Security Work (Architecture)​

MIFARE Classic 1K tags organize memory into 16 sectors, with each sector containing 4 memory blocks of 16 bytes each.

1. Block 0 (Manufacturer Block) Anatomy​

Block 0 in Sector 0 stores critical identity data written during card manufacturing:

+----------------+----+-------+---------+---------------------------------+
| UID (4 bytes)  |BCC | SAK   |  ATQA   | Manufacturer Data (8 bytes)     |
+----------------+----+-------+---------+---------------------------------+
| CF 6A 8F 6C    | 46 |  08   |  04 00  | 62 63 91 8E 6D D4 68 69         |
+----------------+----+-------+---------+---------------------------------+

Field calculation breakdown:

  • UID (CF 6A 8F 6C): 4-byte single-size fixed identifier.
  • BCC (46): Block Check Character calculated by XOR-ing all 4 UID bytes (CF XOR 6A XOR 8F XOR 6C = 46).
  • SAK (08): Select Acknowledge byte confirming MIFARE Classic 1K architecture.
  • ATQA (04 00): Answer To Request byte in little-endian format.

2. PRNG Behavior and Tag Classification​

When authenticating, standard NXP chips generate a dynamic 32-bit random nonce. If a tag repeatedly responds with a fixed static nonce (01200145), it exposes the tag to static nested authentication exploits.

Docker Setup and PM3 Commands​

Here are the complete commands I used to build the Docker image, flash firmware, and test tags.

1. Docker Build and Launch Commands​

# Clone the official Proxmark3 repository
git clone https://github.com/RfidResearchGroup/proxmark3.git
cd proxmark3

# Set generic hardware target platform
echo "PLATFORM=PM3GENERIC" > Makefile.platform

# Build Docker image using Ubuntu 24.04 dockerfile
docker build -t pm3-ubuntu-24.04:1.0 -f docker/ubuntu-24.04/Dockerfile .

# Start interactive Proxmark3 client shell
./pm3-docker.sh

# Flash updated firmware images if needed
./pm3-docker.sh pm3-flash-all

2. Docker Launcher Wrapper Script (pm3-docker.sh)​

To simplify running the Proxmark3 client with automatic USB device mapping (/dev/ttyACM0) and X11 display forwarding, I used the following helper script:

#!/usr/bin/env bash
# Helper script to run Proxmark3 client / flasher inside Docker container

IMAGE_NAME="pm3-ubuntu-24.04:1.0"
HOST_DIR="$(cd "$(dirname "$0")" && pwd)"

# Detect serial devices
DEV_ARGS=()
if [ -c "/dev/ttyACM0" ]; then
    DEV_ARGS+=(--device=/dev/ttyACM0)
fi
for dev in /dev/pm3-*; do
    if [ -c "$dev" ]; then
        DEV_ARGS+=(--device="$dev")
    fi
done

# Pass X11 display if available for GUI plot window
DISPLAY_ARGS=()
if [ -n "$DISPLAY" ]; then
    DISPLAY_ARGS=(-e DISPLAY="$DISPLAY" -v /tmp/.X11-unix:/tmp/.X11-unix)
fi

CMD=("./pm3")
if [ "$#" -gt 0 ]; then
    if [ -f "$1" ]; then
        CMD=("./$1" "${@:2}")
    elif [[ "$1" == "./"* ]]; then
        CMD=("$@")
    else
        CMD=("./pm3" "$@")
    fi
fi

exec docker run \
    --user $(id -u):$(id -g) \
    -e HOME=/tmp \
    --net=host \
    --privileged \
    "${DEV_ARGS[@]}" \
    "${DISPLAY_ARGS[@]}" \
    --volume="$HOST_DIR:/home/rrg/proxmark3" \
    -w /home/rrg/proxmark3 \
    --rm -it \
    "$IMAGE_NAME" "${CMD[@]}"
