Exploring AOSP MD Launcher: My Notes on Building and Multi-Display in Android

July 26, 2026 · 4 min read
Quang Nguyen
Software Engineer & Open Source Enthusiast

Recently, I have been learning about Android system internals. I wanted to understand how Android opens apps on different screens. This topic is very useful for car screens, foldables, and desktop modes.

To learn how it works under the hood, I built and tested MD Launcher (MultiDisplay Launcher). It is an official sample app in the Android Open Source Project (development/samples/MultiDisplay).

In this post, I want to share my notes, what I learned from the code, and how I ran it on an emulator.

What I Learned About MD Launcher​

At first, MD Launcher looks like a simple home screen. But when I read the source code, I found several important features:

  1. Target Display Picker: You can select any connected screen from a dropdown menu. The app uses ActivityOptions.setLaunchDisplayId(displayId) to open new apps on that screen.
  2. Multi-Instance Launching: It has a checkbox to add FLAG_ACTIVITY_MULTIPLE_TASK with FLAG_ACTIVITY_NEW_TASK. This allows running the same app on two screens at the same time.
  3. Secondary Home Category: In AndroidManifest.xml, it uses both android.intent.category.HOME and android.intent.category.SECONDARY_HOME. This lets Android use it as the main home screen for external monitors.
  4. App Pinning: Users can pin app shortcuts onto the main home screen using a simple picker dialog.
  5. Display-Aware Live Wallpaper: The sample wallpaper engine (SampleWallpaper) uses getDisplayContext() to check screen density (densityDpi) whenever screen settings change.
  6. App Drawer Animation: It uses ViewAnimationUtils.createCircularReveal to show a smooth circular animation when opening the app drawer.

Testing on Android Emulator​

To test MD Launcher, I created a secondary display inside the Android Studio Emulator.

Step 1: Setting Up the Second Display​

  1. Start the Android Emulator.
  2. Open Extended Controls (...) > Displays.
  3. Click Add secondary display (1080p or 720p).

Step 2: Exploring the Launcher and Selecting a Display​

When MD Launcher opens on the main screen, it shows the pinned app icons and the display selector at the top. Tapping the bottom button opens the app drawer with all installed apps. Opening the display dropdown shows all connected screens, where I selected Display 2 (the new second screen).

Step 3: Opening Apps on the Second Screen​

With Display 2 selected, tapping an app (like Settings) opens it directly on the second screen.

How the App Works (Architecture)​

MD Launcher uses the standard MVVM (Model-View-ViewModel) pattern with Android Jetpack.

                    +-----------------------+
                    |   LauncherActivity    |
                    +-----------+-----------+
                                |
        +-----------------------+-----------------------+
        |                                               |
+-------v-------------------+               +-----------v---------------+
|     AppListViewModel      |               |  PinnedAppListViewModel   |
+---------------+-----------+               +-----------+---------------+
                |                                       |
    +-----------v-----------+               +-----------v---------------+
    | PackageIntentReceiver |               | SharedPreferences Listener|
    +-----------------------+               +---------------------------+

1. Activity Lifecycle and Launch Options​

In LauncherActivity.java:

  • It uses android:launchMode="singleTop" so the activity is not recreated when screens change.
  • Key code for opening apps on a target screen: 
    void launch(Intent launchIntent) {
        launchIntent.addFlags(Intent.FLAG_ACTIVITY_NEW_TASK);
        if (mNewInstanceCheckBox.isChecked()) {
            launchIntent.addFlags(Intent.FLAG_ACTIVITY_MULTIPLE_TASK);
        }
        final ActivityOptions options = ActivityOptions.makeBasic();
        if (mSelectedDisplayId != Display.INVALID_DISPLAY) {
            options.setLaunchDisplayId(mSelectedDisplayId); // Open on target screen
        }
        startActivity(launchIntent, options.toBundle());
    }

2. Getting the App List (AppListViewModel)​

In AppListViewModel.java:

  • It gets the list of installed apps asynchronously using PackageManager.queryIntentActivities().
  • It uses PackageIntentReceiver to refresh the list automatically when a new app is installed or removed.

3. Saving Pinned Apps (PinnedAppListViewModel)​

In PinnedAppListViewModel.java:

  • It saves pinned apps in SharedPreferences and updates the screen when saved apps change.

Building and Installing​

MD Launcher is configured with Android's Soong build system using Android.bp.

Module Definition (Android.bp)​

android_app {
    name: "MultiDisplay",
    srcs: ["src/**/*.java"],
    static_libs: [
        "com.google.android.material_material",
        "androidx.lifecycle_lifecycle-livedata",
        "androidx.lifecycle_lifecycle-viewmodel",
    ],
    sdk_version: "current",
}

Build Commands​

source build/envsetup.sh
lunch aosp_car_x86_64-userdebug
make MultiDisplay

Install Command​

adb install -r $OUT/system/app/MultiDisplay/MultiDisplay.apk

Summary and Next Steps​

Building and testing MD Launcher helped me understand how Android handles multi-display features. The main key is using ActivityOptions.setLaunchDisplayId() to open apps on specific screens.

I am continuing to learn AOSP internals, system services, and multi-display development.
